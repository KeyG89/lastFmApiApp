# Tutorial UX Standard

The tutorial is the project's business-grade project site and developer cockpit, not a README clone.

## Required Experience

- The first viewport shows project name, project kind, value statement, and current next actions.
- The page explains what the project does before showing commands.
- The page includes an architecture section with project surfaces and responsibilities.
- Workflow stages are visible without reading long paragraphs.
- Commands are grouped by task and easy to copy.
- Diagnostics, CI, GitHub behavior, and auto-improvement are visible.
- The close-item checklist is explicit.
- Mobile layout remains readable and usable.

## UI Rules

- Use a strong header, compact status indicators, and scannable sections.
- Use a colorful but controlled palette with purposeful accents for planning, building, shipping, and improving.
- Use repeated cards only for comparable items such as stages or command groups.
- Use full-width bands or anchored sections for page structure.
- Keep colors restrained but not monochrome.
- Keep copy action-oriented; avoid generic marketing text.
- Use stable spacing and responsive grids so content does not overlap.
